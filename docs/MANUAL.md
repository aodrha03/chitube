## 1. 설치

> 환경별로 짧게 정리한 순서: [시놀로지](install/synology.md) · [리눅스 · 맥](install/linux.md) · [포테이너](install/portainer.md) · [윈도우](install/windows.md)

어느 환경이든 **프로젝트 폴더 전체**(`Dockerfile`, `entrypoint.sh`, `docker-compose.yml`, `app/`, 빈 `config/`·`downloads/` 폴더)를 서버에 두고 `docker-compose.yml` 로 실행합니다. 기본값만으로 동작하므로 파일을 고칠 필요가 없습니다.

설치가 끝나면 브라우저에서 `http://서버주소:8945` 로 접속합니다.

> ⚠ `docker-compose.yml` 의 `restart: unless-stopped` 는 지우지 마세요. 웹 화면의 "재시작해서 업데이트"가 이걸로 다시 켜집니다.

### 리눅스 · 맥 · 윈도우

필요한 것: Docker + Docker Compose v2 (`docker compose` 명령). 윈도우는 WSL 이나 Docker Desktop.

```sh
cd chitube
docker compose up -d --build
```

**저장 위치 · 파일 소유자 바꾸기 (선택)**

```sh
cp .env.example .env
nano .env          # DOWNLOAD_DIR, PUID, PGID 수정
docker compose up -d
```

| 항목 | 설명 | 예 |
|---|---|---|
| `PORT` | 웹 화면 포트 | `8945` |
| `DOWNLOAD_DIR` | 영상 저장 위치 (기본 `./downloads`) | `/mnt/hdd/YouTube`, 맥 외장 `/Volumes/드라이브/YouTube` |
| `PUID` / `PGID` | 저장 파일 소유자. `id` 명령의 uid/gid (맥은 0 그대로) | `1000` / `1000` |
| `TZ` | 시간대 | `Asia/Seoul` |

맥에서 외장 드라이브를 쓰려면 Docker Desktop → 설정 → 파일 공유에 `/Volumes` 를 추가하세요.

### 시놀로지 (DSM 7.2 이상)

1. 패키지 센터에서 **Container Manager** 설치
2. **File Station** 에서 `docker/chitube` 폴더를 만들고 프로젝트 폴더 전체를 업로드
   - 빈 `config/` · `downloads/` 폴더도 꼭 함께 있어야 합니다. 시놀로지는 없는 폴더를 만들어 주지 않아 `Bind mount failed: '.../config' does not exist` 오류가 납니다. 업로드 때 빠졌다면 File Station 에서 직접 만드세요.
3. **Container Manager → 프로젝트 → 생성**
   - 경로: `docker/chitube` (compose 파일이 있는 폴더)
   - 소스: "기존 docker-compose.yml 사용" → 다음 → 완료 (처음엔 빌드로 몇 분 걸림)
4. `http://NAS주소:8945` 접속

> ⚠ **`.env` 의 PUID/PGID 는 기본값 0 그대로 두세요.** 시놀로지는 `config`·`downloads` 폴더를 root 소유로 만들어서, PUID 를 1026 등으로 바꾸면 `unable to open database file` 오류로 컨테이너가 계속 재시작됩니다.

- 다른 공유폴더·USB 에 저장: `.env` 에 `DOWNLOAD_DIR=/volume1/video/YouTube` (USB: `/volumeUSB1/usbshare/YouTube`). 폴더는 File Station 에서 미리 만들어 두세요.
- 파일을 내 계정 소유로 남기고 싶을 때만: SSH 에서 `sudo chown -R 1026:100 <config 폴더> <저장 폴더>` 후 `.env` 에 `PUID=1026`, `PGID=100` (본인 `id` 값).
- 시놀로지 CPU 는 압축이 느린 편입니다. 화질은 **원본 그대로** 또는 **H.264 표준**, 압축 속도는 `veryfast` 이하를 권장합니다. 인텔 모델은 퀵싱크가 자동으로 연결됩니다 (ARM 모델은 CPU 만).

### 포테이너 (Portainer)

이미지를 빌드해야 하므로 웹 편집기(Web editor)만으로는 안 됩니다.

**방법 A — Repository (권장)**

1. Stacks → **Add stack** → 이름 `chitube`
2. Build method: **Repository** → Repository URL 에 이 저장소 주소, Compose path `docker-compose.yml`
3. (선택) Environment variables 에 `DOWNLOAD_DIR`, `PUID`, `PGID`
4. **Deploy the stack**

**방법 B — 서버에서 이미지 빌드 후 스택**

```sh
cd chitube
docker build -t chitube:latest .
```

Stacks → Add stack → Web editor 에 붙여넣기 (경로는 서버 실제 경로로):

```yaml
services:
  youtube:
    image: chitube:latest
    container_name: chitube
    ports:
      - "8945:8000"
    environment:
      - TZ=Asia/Seoul
      - PUID=0
      - PGID=0
    volumes:
      - /opt/chitube/config:/config
      - /mnt/hdd/YouTube:/downloads
      - /:/host                      # 저장 경로를 서버 절대 경로로 쓸 때
    device_cgroup_rules:
      - "c 226:* rmw"                # 인텔 퀵싱크 자동 연결
    restart: unless-stopped
```

## 3. 영상 받기 · 구독

### 바로 받기

YouTube / 치지직 탭 위쪽 칸에 주소를 넣고 **다운로드**. "옵션"을 펼치면 이번 영상만 화질 · 최대 해상도 · 저장 경로를 따로 정할 수 있습니다.

| 플랫폼 | 받을 수 있는 주소 |
|---|---|
| YouTube | 영상, 숏츠, 라이브, 재생목록, 채널 (`youtube.com/@채널`) |
| 치지직 | 다시보기 `chzzk.naver.com/video/번호`, 생방송 `chzzk.naver.com/live/채널ID` |

### 구독

<p align="center"><img src="images/subscriptions.png" alt="구독 채널 관리" width="90%"></p>

채널 주소를 넣고 **＋ 구독**. 옵션에서 받을 종류와 확인 주기를 고릅니다.

- **YouTube**: 동영상 · 숏츠 · 라이브 탭 중 선택, 확인 주기 30분 ~ 하루 (기본 6시간). 확인할 때마다 탭별 최신 15개를 보고 새 영상만 받습니다.
- **YouTube 재생목록**: `playlist?list=…` 또는 `watch?v=…&list=…` 주소로 구독하면 재생목록에 새로 추가된 영상을 받습니다.
- **치지직**: 다시보기 · 생방송 중 선택. 생방송을 고르면 **10초마다** 방송 시작을 확인해 바로 녹화합니다.
- **기존 영상 전부 받기**를 켜면 채널의 옛날 영상까지 오래된 것부터 받습니다 (유튜브는 하루 최대 개수만큼씩 나눠서).
- 구독 채널을 누르면 그 채널만의 화질 · 저장 경로 · 확인 주기를 따로 정할 수 있습니다.
- **필터**: 구독 옵션의 **제목에 포함**(쉼표로 여러 개, 하나라도 들어 있으면) · **제목에서 제외** · **최소 길이(분)** 로 원하는 영상만 받습니다. 예) 포함 `노래, 커버` · 제외 `예고` · 최소 3분. 길이를 모르는 생방송은 길이 조건 없이 받고, 필터는 새로 찾는 영상부터 적용됩니다.
- **방송 시간 패턴**: 구독 채널을 누르면 그동안 녹화한 생방송의 시작 시각을 요일 × 시간 표로 보여 줍니다 (진할수록 자주 방송한 시간).
- 생방송으로 녹화한 치지직 방송은 나중에 올라오는 **다시보기를 또 받지 않습니다.** 단, 녹화가 방송의 90% 미만만 담고 있으면(늦게 발견 · 끊김) 다시보기도 받습니다. 건너뛴 다시보기는 상태 화면의 최근 활동에 남습니다.

### 목록 다루기

- 위쪽 칩으로 전체 · 진행 중 · 대기 · 완료 · 오류 거르기, 검색칸은 제목과 채널명을 찾습니다.
- 정렬: 최근 추가순 · 오래된 추가순 · 업로드 날짜순 · 제목순 · 채널순 · 용량 큰 순 · 길이 긴 순 (대기 목록은 항상 받을 순서)
- **선택** 버튼 → 여러 개 골라 맨 앞으로 · 취소 · 다시 받기 · 목록에서 삭제

### 다시 받기

화질을 바꾸거나 파일이 망가졌을 때 씁니다. 기존 파일은 새로 받기에 **성공한 뒤에만** 지워지고, 실패하면(원본이 지워진 영상 등) 기존 파일이 그대로 남습니다.
끝난 생방송 녹화는 다시 녹화할 수 없으므로 다시 받기가 막혀 있습니다 (치지직이면 다시보기 주소로 받으세요).

## 4. 생방송 녹화

<p align="center"><img src="images/chzzk.png" alt="치지직 생방송 녹화" width="49%"> <img src="images/detail.png" alt="녹화 끊김 기록과 조각 합치기" width="49%"></p>

- 방송 중인 주소를 받거나, 구독한 채널이 방송을 시작하면 그때부터 실시간으로 녹화합니다.
- **■ 녹화 중지 (저장)**: 그때까지 녹화한 부분을 저장하고 멈춥니다.
- **녹화하면서 압축**: 설정 → YouTube / 치지직 탭 → "생방송 녹화하면서 압축" (탭마다 따로). 기본은 **끄기(녹화 후 압축)** 입니다 — 원본 그대로 녹화해 그래픽카드 상태와 상관없이 가장 안정적이고, 방송이 끝난 뒤 차례로 압축합니다 (녹화 중엔 원본 크기만큼 공간을 씀). 켜면 그래픽카드로, 따라가지 못하면 CPU 로, 둘 다 안 되면 녹화 후 압축합니다.
- **끊김 이어 녹화**: 방송은 계속되는데 녹화가 끊기면 몇 초 안에 새 파일(`…-p2`, `…-p3`)로 이어서 녹화합니다. 영상 정보 창의 **녹화 끊김 기록**에 끊긴 시각과 빠진 시간이 표시됩니다.
- **자동 합치기**: 방송이 끝나면 나뉜 조각을 자동으로 한 파일로 합칩니다 (형식이 같을 때만 · 화질 그대로). 형식이 다르면 로그에 알리고 그대로 두니 아래 버튼으로 합치세요. 설정 → 공통 → "끊긴 녹화 자동 합치기"로 끌 수 있습니다.
- **조각 합치기**: 끊김 기록의 "조각 N개 한 파일로 합치기". 형식이 같으면 화질 그대로 바로 이어 붙이고, 다르면(처음 조각은 원본, 다음 조각은 압축본 등) 지금 화질 설정으로 다시 압축해 합칠지 묻습니다. 빠진 구간은 채워지지 않습니다.
- **녹화 멈춤 감시**: 녹화 파일이 45초(설정 → 공통 → "녹화 멈춤 판단") 동안 커지지 않으면(예: 녹화 중인 파일을 복사 · 이동해 녹화가 멈춤) 그때까지 녹화분을 저장하고 새 파일로 이어서 녹화합니다.
- **끊긴 녹화는 다시보기로 메우기** (설정 → 공통, 기본 켜짐): 녹화가 한 번이라도 끊겼던 치지직 방송은 방송이 끝난 뒤 올라오는 **다시보기도 받아** 빠진 부분 없는 판을 확보합니다. 생방송만 구독한 채널도 그 방송의 다시보기만 찾아 받습니다 (최근 3일). 다시보기를 받은 뒤 끊긴 녹화본은 그대로 두거나(기본) 지울 수 있습니다.
- **업데이트할 때 녹화 보호**: 상태 → 업데이트 버튼을 녹화 중에 누르면 "녹화가 모두 끝나면 자동으로 업데이트" 또는 "지금 바로"를 고릅니다. 재시작으로 끊긴 녹화 압축은 재시작 후 이어서 압축합니다. (컨테이너를 직접 재시작 · 중지하면 녹화는 끊기니, 녹화가 없을 때 하세요)
- **부하 보호**: CPU 나 그래픽카드 압축기가 3분째 95% 이상이고 생방송을 녹화 중이면, 새 압축은 잠시 미루고 녹화에 자원을 줍니다.
- **전체 감시**: 1분마다 받는 중인 작업 전부를 확인해, 진행이 전혀 없으면(녹화 3분 · 다운로드 20분 · 압축 30분) 그 작업을 정리합니다 — 녹화는 녹화분 보존 후 이어서, 다운로드는 조금 뒤 다시 받습니다. 받기 스레드가 사라진 채 "받는 중"으로 남은 작업은 대기열로 되돌립니다.
- **방송 시작 직후**: 치지직이 막 시작한 방송을 잠깐 '종료'로 알려 줘 녹화가 실패하면, 같은 녹화를 10초 뒤 다시 시도합니다 (최대 1분).
- **녹화 썸네일**: 녹화 파일 옆에 썸네일이 없으면(치지직 생방송 썸네일은 방송이 끝나면 사라짐) 녹화 장면 하나로 만들어 둡니다.
- **미리보기**: 받는 중 · 녹화 중인 영상의 정보 창에서 "▶ 지금 받는 부분 확인" → 최근 10초를 저장되는 화질 그대로 재생합니다.

### 녹화 중인 파일을 복사 · 이동할 때

**받는 중 · 녹화 중인 파일은 어떤 OS 에서든 복사하거나 옮기지 마세요.** 복사 · 이동하는 방법(탐색기 · Finder · 네트워크 공유)과 Docker 가 폴더를 연결하는 방식에 따라 녹화가 멈추거나, 끝날 때 파일을 찾지 못해 정리 · 압축이 안 될 수 있습니다. 녹화 중 확인은 영상 정보 창의 **▶ 지금 받는 부분 확인**(미리보기)을 쓰고, 복사 · 이동은 카드가 **완료**가 된 뒤에 하세요. (녹화가 멈추면 45초 뒤(설정으로 바꿀 수 있음) 자동으로 그때까지 녹화분을 저장하고 새 파일로 이어서 녹화하지만, 멈춘 동안은 빠집니다)

## 5. 로그인 (멤버십 · 성인 인증 영상)

YouTube / 치지직 탭 → **🔑 로그인** → **브라우저 열기** → 새 창에 뜬 브라우저(서버 안에서 실행)에서 구글 / 네이버로 평소처럼 로그인 (2단계 인증 · 네이버 QR 로그인 가능) → 원래 화면에서 **로그인 완료** → "✓ 로그인됨" 확인.

- 로그인 정보는 `config/cookies_youtube.txt`, `config/cookies_chzzk.txt` 에 저장됩니다. **계정 정보이니 남에게 주지 마세요.**
- 네이버는 로그인 화면에서 **로그인 상태 유지**를 체크하면 더 오래 갑니다. 네이버에서 로그아웃하면 저장한 로그인도 무효가 되니 창만 닫으세요.
- 로그인한 지 오래되면(기본 14일) "다시 로그인 권장"이 뜹니다. 같은 순서로 다시 로그인하면 됩니다.
- 로그인이 꼬였으면 **로그인 완전 초기화** 후 처음부터.
- 브라우저 대신 확장 프로그램(Get cookies.txt LOCALLY)으로 내보낸 cookies.txt 를 붙여넣어도 됩니다.
- 로그인한 채로 받다 실패하는 영상은 자동으로 로그인 없이 한 번 더 시도합니다.
- 치지직 성인 영상을 로그인 없이 받으면 "성인 인증 필요"로 멈추고 자동 재시도하지 않습니다. 로그인 후 **다시 받기**.

## 6. 화질 · 압축 · 하드웨어 가속

### 화질 프리셋

<p align="center"><img src="images/settings.png" alt="화질 설정" width="90%"></p>

설정 → YouTube / 치지직 탭 → 화질. 코덱 탭을 고른 뒤 프리셋을 고릅니다. (용량은 원본 대비, 조용한 영상 / 움직임 많은 영상 실측)

| 코덱 | 프리셋 | 설명 |
|---|---|---|
| **H.265** (추천) | 원본급 | 원본과 구분 어려움 · 용량 86% / 100% |
| | 고화질 | 거의 원본 그대로 · 77% / 93% |
| | **표준** (기본) | 조용한 영상은 원본급, 빠른 장면 아주 약간 · 69% / 73% |
| | 용량 절약 | 빠른 장면에서 뭉개짐 보임 · 56% / 58% |
| H.264 | 원본급 · 표준 | 거의 모든 기기에서 재생, 용량은 원본 정도 |

| 기타 | 원본 그대로 | 다시 압축하지 않음 · 화질 손실 0 · 용량 가장 큼 |
| | 직접 설정 | 공통 탭 → 고급 설정의 코덱 · CRF · 최대 크기 |

- 최대 해상도 기본 1080p (짧은 변 기준이라 세로 숏츠도 그대로).
- 적용 순서: **공통 → YouTube/치지직 탭 → 구독 채널별 → 바로 받기 옵션** (뒤에 정한 것이 이김, 비워 두면 앞 단계 값).
- 압축해도 원본보다 작아지지 않으면 원본 화질을 그대로 둡니다.
- 유튜브에서 요청한 화질을 못 받으면 받을 수 있는 가장 높은 화질로 받습니다.

### 압축 방식

설정 → **YouTube / 치지직 탭**마다 따로 정합니다 (예: 유튜브는 받으면서 압축, 치지직 생방송은 녹화하면서 압축 끄기).

- **압축 방식**: **받으면서 바로 압축**(기본 · 임시 파일 없음) / 다 받은 뒤 압축(원본을 잠깐 저장)
- **생방송 녹화하면서 압축**: 끄기 · 녹화 후 압축(기본 · 가장 안정적) / 그래픽카드로, 한계면 CPU 로 / 그래픽카드로만
- **그래픽카드로 동시에 녹화하면서 압축** (설정 → 공통, 기본 3개): 그래픽카드의 압축기는 하나를 나눠 쓰기 때문에, 생방송을 너무 많이 동시에 압축하면 다 같이 실시간을 못 따라가 녹화가 멈춥니다. 이 개수를 넘는 생방송은 **원본으로 녹화하고 방송이 끝난 뒤 압축**합니다. 그래픽카드로 녹화 중인 생방송이 있는 동안 다른 압축(다 받은 뒤 · 녹화 후 · 나중에 압축)은 그래픽카드를 비켜 CPU 로 합니다. 보급형 카드(예: RTX A400 · GTX 1650)는 1080p 생방송 2~3개, 그 이상은 카드에 따라 늘려 보세요.
- **동시 압축**: 다 받은 뒤 · 녹화 후 · 나중에 압축하는 개수. **동시 다운로드와 따로** 세서, 압축하는 동안에도 다음 영상을 받습니다 (예전엔 압축이 끝나야 다음 다운로드가 시작됐음). 기다리는 영상은 "압축 대기"로 보입니다.

### 나중에 압축

원본 그대로 받은 영상 · 녹화 · 다시보기를 나중에 압축할 수 있습니다 (용량이 부족해졌을 때 등).

- 영상 정보 창 아래의 **압축할 화질**을 고르고 **나중에 압축**
- 여러 개: 목록의 **선택** → 영상 고르기 → 선택 막대의 화질을 고르고 **나중에 압축** (완료된 영상만)
- 동시 압축 개수만큼 차례로 압축합니다. **작아질 때만** 압축본으로 바꾸고 원본은 지웁니다 (커지면 원본 그대로 · 최근 활동에 표시). 압축 중에는 영상 정보 창의 **압축 취소**로 멈출 수 있습니다 (원본 그대로).

### 하드웨어 가속

설정 → 공통 → 하드웨어 가속: 자동(엔비디아 → 인텔 퀵싱크 → CPU) / CPU / 엔비디아 / 인텔 퀵싱크. 실제로 쓰는 장치는 상태 탭에 표시됩니다.

| 서버 | 할 일 |
|---|---|
| 내장 그래픽 없는 CPU (제온 등), ARM NAS | 없음 — 자동으로 CPU |
| 인텔 내장 그래픽 (시놀로지 인텔 모델, 코어 i 시리즈 등) | 없음 — 서버에 `/dev/dri` 가 있으면 자동 연결 |
| 엔비디아 그래픽카드 | 서버에 NVIDIA 드라이버 + [NVIDIA Container Toolkit](https://docs.nvidia.com/datacenter/cloud-native/container-toolkit/latest/install-guide.html) 설치 후 한 번만:<br>`sudo nvidia-ctk runtime configure --runtime=docker --set-as-default && sudo systemctl restart docker` |
| 맥 (애플 메탈) · 윈도우 Docker Desktop | 없음 — 도커 구조상 컨테이너가 GPU 를 못 써서 CPU 사용 |

하드웨어 압축이 실패하면 자동으로 CPU 로 다시 압축합니다. 안 되는 이유는 상태 탭 → "하드웨어 가속 안 되는 이유"에서 볼 수 있습니다.

### 자막

설정 → YouTube → 자막: **전부**(기본 · 직접 만든 자막 + 자동 생성 원어) / 직접 만든 자막만 / 받지 않음. 모두 `.srt` 로 저장됩니다.

### 챕터 · 광고 구간 표시

- 유튜브 영상에 챕터(설명란의 `00:00 시작` 같은 타임스탬프)가 있으면 영상 파일에 챕터로 넣습니다. Plex · VLC · 팟플레이어 등에서 구간 이동에 씁니다.
- 설정 → 공통 → **유튜브 광고 구간 챕터 표시**를 켜면 [SponsorBlock](https://sponsor.ajay.app)(사용자들이 제보한 공개 DB)에서 광고 · 협찬 구간을 찾아 챕터로 **표시만** 합니다. 영상은 자르지 않습니다. 기본은 꺼짐이며, 켜면 영상 ID 일부(해시)가 SponsorBlock 서버로 전송됩니다.

## 7. 저장 경로 · Plex · Jellyfin

### 저장 경로

- `/` 로 시작하면 서버의 그 경로 그대로 (예: `/volume1/video/YouTube`) — compose 의 `- /:/host` 덕분
- 그 밖(예: `YouTube`)은 다운로드 폴더(`DOWNLOAD_DIR`) 안
- 시놀로지에서 `/:/host` 연결이 거부되면 그 줄을 `- /volume1:/host/volume1` 처럼 쓰는 볼륨만으로 바꾸세요.
- 남은 공간이 설정값(기본 20GB)보다 적으면 그 디스크로 가는 새 다운로드 · 녹화를 멈추고, 공간이 생기면 자동으로 다시 시작합니다.

### 저장 구조

```
YouTube/채널명/poster.jpg, tvshow.nfo
YouTube/채널명/Season 2026/채널명 - s2026e101801 - 2026-10-18 - 제목 [영상ID]/
    채널명 - s2026e101801 - 2026-10-18 - 제목 [영상ID].mp4   (+ .jpg .nfo .ko.srt)

Chzzk/스트리머/2026-10-20 - 제목/2026-10-20 - 제목 [ID].mp4   (+ .jpg)
```

시즌 = 업로드 연도, 에피소드 = 월일 + 같은 날 순번. 설정 → 공통 → "영상마다 폴더 만들기"를 끄면 시즌 폴더에 바로 저장합니다. 이미 받은 영상은 설정 → 관리 → "이미 받은 영상을 영상별 폴더로 정리"로 옮길 수 있습니다.

### Plex · Jellyfin (Plex 1.43 · Jellyfin 12.2 에서 확인)

라이브러리 폴더로 **저장 폴더**(기본 `YouTube`)를 추가하세요. 다운로드 폴더 최상위를 넣으면 `YouTube` 같은 폴더 이름이 쇼로 잡힙니다.

- **Plex**: 라이브러리 추가 → **TV 프로그램** → 고급 → 스캐너 **Plex TV Series**, 에이전트 **Personal Media**
- **Jellyfin**: 라이브러리 추가 → 콘텐츠 유형 **프로그램(Shows)** → 메타데이터 다운로더(TheMovieDb 등)는 모두 **끄기** (nfo 로 충분)

| 파일 | 내용 | Plex | Jellyfin |
|---|---|---|---|
| `….mp4` | 영상 + 제목 · 설명 · 방송일 · 채널 태그 | ✅ | ✅ |
| `….nfo` | 제목 · 설명 · 방송일 · 시즌/에피소드 · 길이 · 영상 ID | — | ✅ |
| `….jpg` | 에피소드 썸네일 | ✅ | ✅ |
| `….ko.srt` | 자막 (언어별) | ✅ | ✅ |
| `채널/poster.jpg` | 쇼 포스터 (채널 프로필 사진) | ✅ | ✅ |
| `채널/tvshow.nfo` | 쇼 정보 | — | ✅ |

## 10. 설정 백업 · 업데이트

### 백업 · 복원

설정 → 공통 → 관리 → **설정·구독 백업 파일 받기** / **백업 불러오기**. 서버를 옮기거나 다시 설치할 때 씁니다. 로그인 정보와 받은 영상 목록은 들어가지 않습니다 (불러올 때 이미 있는 구독은 건너뜀).

### 업데이트

| 무엇 | 방법 |
|---|---|
| 치튜브 새 버전 | 상태 탭이 12시간마다 GitHub 최신 릴리스를 확인해, 새 버전이 있으면 "상태" 탭에 ● 와 **새 버전 받기** 버튼 → 릴리스 페이지에서 내 환경 파일을 받아 덮어쓰기 |
| yt-dlp · deno (유튜브 변경 대응) | 상태 탭 → **재시작해서 업데이트** (또는 컨테이너 재시작). 12시간마다 새 버전을 확인해 "상태" 탭에 ● 표시 |
| 이 프로그램 · ffmpeg | 새 파일로 덮어쓰고 `docker compose up -d --build` (시놀로지: 프로젝트 정지 → 빌드 → 시작 · 포테이너: Re-pull & redeploy). 설정 · DB 는 `config/` 에 그대로 |

## 11. 문제 해결

| 증상 | 해결 |
|---|---|
| 원인을 모르는 문제 | 상태 → 최근 활동의 **진단 파일 받기** (로그 · 상태 · 설정 · 진행 중인 작업을 한 파일로, 로그인 정보는 빠짐) — 문의할 때 이 파일 하나만 보내 주세요. 로그만은 **로그 파일 받기** (`config/logs/` 에도 있음) |
| 상태 화면 위에 "⚠ 확인해 볼 설정" | 녹화가 멈추거나 차단될 위험이 큰 설정 조합 · 남은 공간 안내입니다. 안내대로 바꾸면 사라집니다 |
| 네트워크 · 서버 오류(시간 초과 · 503 등)로 실패 | 자동으로 1분 → 5분 → 15분 뒤 다시 받습니다. 그래도 안 되면 점검 때 다시 시도 |
| 시놀로지에서 `Bind mount failed: ... does not exist` | 프로젝트 폴더 안에 빈 `config/` · `downloads/` 폴더를 만드세요 |
| `unable to open database file`, 컨테이너가 계속 재시작 | `.env` 의 PUID/PGID 를 0 으로 되돌리거나 폴더 소유자를 맞추세요 (로그에 `[권한 오류]` 로 원인 표시) |
| 유튜브가 "봇이 아닌지 확인" · 계속 실패 | 자동으로 쉬는 중입니다. 기다리거나, 유튜브 로그인 · 동시 다운로드 1개로 |
| "멤버십 전용" · "연령 확인 필요" | 해당 계정으로 [로그인](#5-로그인-멤버십--성인-인증-영상) |
| 치지직 "성인 인증 필요" | 성인 인증된 네이버 계정으로 로그인 후 다시 받기 |
| 재생이 안 됨 (H.265) | 사파리 · 엣지 · 하드웨어 지원 크롬에서 재생됩니다. "파일 받기"로 저장해 재생하거나 H.264 프리셋을 쓰세요 |
| 하드웨어 가속이 안 잡힘 | 상태 탭 → "하드웨어 가속 안 되는 이유" 확인 ([하드웨어 가속](#하드웨어-가속) 표 참고) |
| 새 다운로드가 멈춤 | 디스크 공간 부족 안내가 떠 있는지 확인 → 공간을 비우거나 최소 여유 공간 설정을 낮추세요 |

로그 보기 · 자체 테스트:

```sh
docker compose logs -f
docker exec chitube python test_main.py
```
